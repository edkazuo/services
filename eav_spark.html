EAV sem PIVOT: o problema que 3 tabelas nunca resolveram de graça

Modelar atributo dinâmico de produto em SQL relacional sempre exigiu Entity-Attribute-Value — e o preço de "montar a tabela de volta" era um PIVOT caro, com schema que precisa ser conhecido antes de rodar. Complex data type no Spark resolve isso sem transpose nenhum.

modelo_eav.diff
- tb_produto (id, nome) - tb_dicionario_coluna (id, nome, tipo) - tb_valor (id_produto, id_coluna, valor) - -- PIVOT dinâmico exige SQL montado em runtime + df_produto: id, nome, atributos: MapType<String, String> + -- sem PIVOT, sem schema fixo, sem tabela extra
O problema

Por que EAV em SQL relacional sempre doeu

Modelo clássico

Três tabelas separadas — produto, dicionário de coluna, valor — permitem atributo dinâmico por produto sem alterar schema. Mas "montar" a visão tabular de volta exige PIVOT, que precisa saber as colunas de saída antes de executar — geralmente resolvido com SQL dinâmico montado em runtime, caro e frágil.

Complex data type

O atributo dinâmico vive dentro da própria linha, como MapType ou Array<Struct>. Não existe mais transpose — explode() e acesso por chave resolvem sob demanda, sem nunca precisar de schema fixo.

Na prática

Os dois sentidos: explodir e reagrupar

O ganho real aparece quando você precisa ir e voltar entre formato "largo" (uma linha por produto) e "longo" (uma linha por atributo) — sem nunca escrever um PIVOT.

explode() — de MapType para formato longo
df_long = df_map.select(
    "id_produto", "nome",
    F.explode("atributos").alias("nome_coluna", "valor")
)
# uma linha por atributo, sem tabela de dicionário separada
map_from_entries() — o "pivot dinâmico" sem PIVOT
df_reagrupado = (
    df_long
    .groupBy("id_produto", "nome")
    .agg(F.map_from_entries(
        F.collect_list(F.struct("nome_coluna", "valor"))
    ).alias("atributos"))
)
# volta pro formato largo -- funciona com QUALQUER conjunto
# de atributos, mesmo diferente entre produtos, sem PIVOT
Referência rápida

Funções nativas do Spark para complex type

map_keys / map_values
Lista as chaves ou valores de um MapType — útil para inspecionar quais atributos um produto tem, sem saber antecipadamente.
map_contains_key
Filtra linhas onde um atributo específico existe — equivalente a um WHERE condicional no modelo EAV antigo, sem JOIN.
element_at
Acessa uma chave específica do mapa de forma segura — retorna NULL se não existir, sem lançar erro.
transform_values
Aplica uma função a todos os valores do mapa de uma vez — por exemplo, normalizar texto, sem precisar explodir e reagrupar.
try_cast
Conversão de tipo que retorna NULL em vez de lançar exceção — essencial ao converter valor de atributo dinâmico, onde tipo real pode variar por linha.
Atenção real de implementação: em when().otherwise(), o Spark tenta unificar o tipo das duas branches — se uma vira decimal e a outra continua string, ele tenta converter tudo, e quebra em valores que nunca deveriam ser numéricos. A correção é usar try_cast em vez de cast, e omitir o otherwise() quando o tipo de destino diverge.
